# Fifty+ strategy

## 概要

**Fifty+** は、2025年に山田佳江が考案した実験的な売買ストラテジーです。

発想の出発点はとても単純です。

> コイントスのような 50:50 の方向当てに、AIがほんの少しでも再現性のある優位性を加えられるなら、リスクリワード 1:1 でも長期的な期待値をプラスにできるのではないか。

Fifty+ は、この仮説をできるだけ単純な形で検証します。

通常の自動売買のように「今は取引しない」「ポジション量を増減する」「コストが高いので見送る」といった判断をAIへ任せません。AIの仕事は、**次に上側と下側のどちらの対称境界へ先に到達するかを選ぶことだけ**です。

## 基本ルール

1. ポジションを持っていなければ、AIへ次の方向を聞く。
2. AIは **UP / DOWN のどちらか一方を必ず選ぶ**。
3. UPならLONG、DOWNならSHORTを1ポジション建てる。
4. 利確幅と損切り幅は同じにする。
5. TPまたはSLで決済されたら、その時点で次のUP / DOWNをAIへ聞く。
6. 以後これを繰り返す。

つまり、原則として**常に1つのポジションを持つ**ストラテジーです。

Fifty+ には「FLAT」「WAIT」「KEEP」「COST_TOO_HIGH」のような棄権用の選択肢はありません。これは積極的に取引させるためだけではなく、**AIの方向判定そのものに50%を超える優位性があるかを測りやすくするため**です。

## なぜ「50%超え」なのか

利確と損切りが完全に同じ幅で、1回の勝ちを +1、負けを -1 と単純化すると、勝率を `p` とした1回あたりの期待値は

```text
期待値 = p × 1 - (1 - p) × 1
      = 2p - 1
```

になります。

- 勝率 50% → 期待値 0
- 勝率 51% → 期待値 +0.02
- 勝率 55% → 期待値 +0.10

このため、十分な試行回数の中でAIが方向判定にわずかでも安定した優位性を持ち、**実現したネット損益が対称な1:1に保たれるなら、50%を超える勝率が意味を持つ**というのがFifty+の中心仮説です。

ただし、短い試行で50%を超えただけでは優位性の証明にはなりません。相場環境による偏り、偶然、データの偏り、執行差などを分けて検証する必要があります。

## JevPip版 Fifty+

JevPipでは、この考え方をJevを使ったpaper tradingとして実装しています。

### AIが決めるもの

Jevが決めるのは次の二択だけです。

- `UP` → LONG
- `DOWN` → SHORT

数量、コスト計算、TP/SL、口座計算、約定判定はコード側が管理します。

### AIが決めないもの

Fifty+ではJevに次を判断させません。

- 取引するか、しないか
- FLATで待つか
- ポジション数量
- コストが高いので見送るか
- 利確幅と損切り幅
- ポジション保有中の細かな売買判断

この分離により、結果を「AIの方向判定が50%を超えたか」という比較的明快な問いへ寄せています。

## 勝負幅

### FX

FXでは、Fifty+の勝負幅をpipsで指定します。

例:

```text
勝負幅: 5 pips
LONG:
  net +5 pips → WIN
  net -5 pips → LOSS
```

### BTC/JPY

BTC/JPYでは、勝負幅を円のネット損益で指定します。

例:

```text
勝負額: 500円
LONG / SHORT:
  net +500円 → WIN
  net -500円 → LOSS
```

JevPipのpaper brokerでは、spread、設定slippage、銘柄ごとのreference feeを反映した**ネット損益**でFifty+のTP/SLを判定します。

そのため、Fifty+でいう「1:1」は単なるチャート上の値幅ではなく、paper model上のコストを含めた対称な損益境界を指します。

実市場では、tick間の価格飛び、板の厚み、部分約定、実slippage、注文遅延などにより、実現損益が厳密な1:1にならない可能性があります。

## spread・勝負幅・放置実験の運用メモ

Fifty+はネット損益の ±X で決済するため、勝負幅を小さくするほどspread・手数料・slippageの比率が大きくなります。

新規建玉直後のネット損益は、すでに往復コスト分だけマイナス側から始まります。たとえばFXで勝負幅が5 pips、推定往復コストが3 pipsなら、価格変化だけで見るとWIN側まで進む距離はLOSS側よりかなり長くなります。

このため、JevPipでは次をコード側の安全条件として扱います。

- 設定した最大spreadを超えている間は新規取引しない
- 推定往復コストが勝負幅以上なら、建てた瞬間に損切り境界へ入るため新規ラウンドを開始しない
- 上記の待機中はJev APIも呼ばない
- 条件が改善すれば自動的に再開する

### 放置して観測する場合

短い勝負幅はラウンド数を増やせる一方、コストの影響を強く受けます。

数時間そのまま動かして観測する用途では、5 pipsだけに固定せず、**10 pips / 15 pipsなど大きめの勝負幅も比較対象にする**のがよい研究条件です。これは利益を保証する推奨値ではなく、コスト比率とラウンド所要時間の違いを見るための実験設定です。

比較時には少なくとも次を同時に記録します。

- 勝負幅
- 実spread
- 推定往復コスト
- WIN / LOSS
- 純損益
- 1ラウンドの時間
- Jevの方向別勝率
- random controlとの差

特に、コストがある状態ではランダム方向の実現WIN率が必ずしも50%近辺になるとは限りません。Fifty+の評価では、単なる「50%超え」だけでなく、**同じコスト条件のrandom controlとの差**を見ることが重要です。

### 2026-09-21のUI確認で得た例

JevPipの実画面確認中に、以下を観測しました。

- USD/JPYでspread約9.9 pips、勝負幅10 pips
  - spreadとreference feeだけで新規直後のネット損益が損切り境界を超え、即決済と再エントリーを繰り返した
  - この観察を受け、往復コストが勝負幅以上なら新規ラウンドを開始しない安全弁を追加した
- EUR/JPYでspread約2.7 pips、勝負幅5 pips
  - 取引自体は成立するが、勝負幅に対するコスト比率が大きく、短時間に複数回の損切りが発生した
  - 挙動自体はFifty+のルールどおりであり、「小さい勝負幅ほどコストの影響が強い」ことを目視確認できた

この日は日本の祝日（敬老の日）で、確認時刻も日本時間の早朝でした。GMOクリック証券は、休日・祝日や早朝など市場流動性が低い状況ではspreadが拡大する場合があると案内しています。

ただし、この日のspread拡大を祝日だけに帰属させることはできません。時間帯、市場参加者、ニュース、通貨ペア固有の流動性など複数要因があり得るため、研究ログでは「祝日 / 時間帯 / 実spread」を別々に記録します。

参考:

- 内閣府「国民の祝日について」: 2026-09-21は敬老の日
- GMOクリック証券「FXのスプレッドとは？」: 早朝・休日・祝日など流動性低下時にspreadが広がる可能性を説明
- GMOクリック証券「FXネオ」: 原則固定spreadには適用時間帯と例外がある

## Jevを呼ぶタイミング

Fifty+では、Jevを一定時間ごとに呼び続けません。

```text
FLAT
  ↓
Jev: UP / DOWN
  ↓
1ポジション
  ↓
TP または SL
  ↓
FLAT
  ↓
次のJev判断
```

ポジション保有中はJev APIを呼ばないため、デイトレ/スキャルピングモードのように同じ市場状態を何度も読み直す必要がありません。

これはFifty+の実験設計を単純にすると同時に、API token消費も「経過時間」ではなく**ラウンド数**に近づけます。

## この実験で見たいもの

Fifty+で特に見たいのは次です。

- JevのUP / DOWN勝率は長期的に50%を超えるか
- 勝率の優位性は特定の銘柄・時間帯・相場状態だけに偏っていないか
- 勝負幅を変えると勝率や1ラウンドの所要時間がどう変わるか
- FXとBTCで同じ傾向が出るか
- APIコストを含めても研究として継続可能なtoken効率になるか
- 単純なランダム方向選択と比べてJevに再現性のある差があるか

損益だけでなく、**方向判定そのものの統計**を見ることが重要です。

## Fifty+ と派生版

Fifty+には、過去にADX、DI、ローソク足、時間帯、経済イベント回避などを加えた派生版もあります。

JevPipの初期実装では、まずそれらを入れず、

> AIにUP / DOWNだけを選ばせたとき、50:50の基準を超えられるか

というFifty+の核を優先して実装しています。

将来フィルタを追加する場合も、まずこの単純版をbaselineとして残し、どの条件が本当に優位性へ寄与したか比較できる形を目指します。

## 注意

Fifty+は**収益を保証する手法ではなく、仮説検証のための実験ストラテジー**です。

50%を超える勝率が一時的に観測されても、それだけで将来の優位性や実売買での利益を意味しません。JevPip自体も現在はpaper tradingを前提としており、実注文は行いません。
