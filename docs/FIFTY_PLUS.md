# Fifty+ strategy

## 概要

**Fifty+** は、2025年に山田佳江が考案した実験的な売買ストラテジーです。

発想の出発点はとても単純です。

> コイントスのような 50:50 の方向当てに、AIがほんの少しでも再現性のある優位性を加えられるなら、リスクリワード 1:1 でも長期的な期待値をプラスにできるのではないか。

Fifty+ は、この仮説をできるだけ単純な形で検証します。

通常の自動売買のように「今は取引しない」「ポジション量を増減する」「コストが高いので見送る」といった判断をAIへ任せません。AIの仕事は、**次に上側と下側のどちらの対称境界へ先に到達するかを選ぶことだけ**です。

## 基本ルール

1. ポジションを持っていなければ、設定した**方向源**から次の方向を得る。
2. 方向源は **UP / DOWN のどちらか一方を必ず選ぶ**。
3. UPならLONG、DOWNならSHORTを1ポジション建てる。
4. 利確幅と損切り幅は同じにする。
5. TPまたはSLで決済されたら、設定した再判断待機時間だけFLATで待つ。
6. 待機後に次のUP / DOWNを決め、以後これを繰り返す。

つまり、**1ポジションずつ持ち、ラウンド間には短い待機を入れられる**ストラテジーです。JevPipの初期値は60秒です。

Fifty+ には、方向源に「FLAT」「WAIT」「KEEP」「COST_TOO_HIGH」のような棄権用の選択肢を持たせません。これは積極的に取引させるためだけではなく、**方向判定そのものを同じ執行条件で比較しやすくするため**です。Jevを方向源にした場合は、AIの方向判定が50%を超える優位性を持つかを主に検証します。

## なぜ「50%超え」なのか

利確と損切りが完全に同じ幅で、1回の勝ちを +1、負けを -1 と単純化すると、勝率を `p` とした1回あたりの期待値は

```text
期待値 = p × 1 - (1 - p) × 1
      = 2p - 1
```

になります。

- 勝率 50% → 期待値 0
- 勝率 51% → 期待値 +0.02
- 勝率 55% → 期待値 +0.10

このため、十分な試行回数の中でAIが方向判定にわずかでも安定した優位性を持ち、**実現したネット損益が対称な1:1に保たれるなら、50%を超える勝率が意味を持つ**というのがFifty+の中心仮説です。

ただし、短い試行で50%を超えただけでは優位性の証明にはなりません。相場環境による偏り、偶然、データの偏り、執行差などを分けて検証する必要があります。

## JevPip版 Fifty+

JevPipでは、Fifty+の売買骨格と方向源を分離しています。現在のUIでは次の2系統を使えます。

- **Jevモード / Fifty+**: Jev APIがUP / DOWNを選ぶ
- **スピリチュアルモード**: Jev APIを呼ばず、月相・太陽星座・ランダムタロット・コイントスがUP / DOWNを選ぶ

どちらも数量、勝負幅、決済、待機、spread / cost gate、最大DD、レバレッジ、口座会計は同じFifty+コード側が管理します。

### Jevが決めるもの

Jevが決めるのは次の二択だけです。

- `UP` → LONG
- `DOWN` → SHORT

質問時には、そのラウンドで設定されている対称NET勝負幅と、LONG / SHORTそれぞれの独立した勝敗条件をコード側で明示します。たとえばFXで勝負幅が5 pipsなら、「LONGを建てた場合にそのLONG自身のnet +5 pipsがnet -5 pipsより先に到達するか」と、「SHORTを建てた場合にそのSHORT自身のnet +5 pipsがnet -5 pipsより先に到達するか」を別々に評価させ、そのうえでTP先着がより見込める方向を選ばせます。spread / fee / slippageがあるため、LONGが負けてもSHORTなら必ず勝ちとは限らず、両方向がそれぞれSL先着になる経路もあります。Jevが答えた方向を建てた後、brokerは同じNET ±5 pips境界で決済します。

数量、コスト計算、TP/SL、口座計算、約定判定はコード側が管理します。

### 方向別の答え合わせ

live Fifty+とraw tick Jev BTでは、実際に選んだ方向の売買とは別に、同じentry条件からLONG / SHORT双方の仮想tradeを追跡します。各方向について `take_profit_first / stop_loss_first / unresolved` と決着時間を保存し、片側の結果を反転してもう片側の正解にはしません。セッション終了・データ終端などで未決着なら勝敗へ無理に分類しません。

liveの結果は `data/fifty_outcomes/<instrument>/YYYY-MM-DD.jsonl`、Jev BTの結果は既存のreplay JSONLへ保存します。ChoiceのUP / DOWN確率は二択の相対選好であり、LONG / SHORTそれぞれの実測勝率や校正済み確率ではありません。

### AIが決めないもの

Fifty+ではJevに次を判断させません。

- 取引するか、しないか
- FLATで待つか
- ポジション数量
- コストが高いので見送るか
- 利確幅と損切り幅
- ポジション保有中の細かな売買判断

この分離により、Jev版では結果を「AIの方向判定が50%を超えたか」という比較的明快な問いへ寄せています。

### Jevへ見せる trader context

方向の選び方そのものはJevへ固定ルールとして教えません。その代わり、一般的な短期トレーダーが参照できる程度の情報を広く渡し、**どの情報を重視し、どれをノイズとして無視するかもJev自身へ任せます**。

live Jev Fifty+では、判断時点で利用可能な範囲から主に次を渡します。

- 現在のbid / ask / mid / spread
- 直近40 tick
- 1分 / 5分 / 15分 / 1時間のmulti-timeframe OHLC
- 各時間足のSMA20 / SMA50 / SMA200、RSI14、ATR14
- 直近20本の高値・安値とrange内の現在位置
- UTC / 東京 / ロンドン / ニューヨークの現在時刻と曜日
- 現在position
- balance / equity、確定・含み損益、fees / slippage
- closed trades、wins / losses、win rate、profit factor、平均損益、最大DD
- recent executions、exit reason集計、PnL breakdown
- broker側のcost model / constraints
- 「公式イベントを見る」がONなら、既存の公式event context

multi-timeframe履歴は起動時にPublic historical KLineからwarmupし、その後はlive tickで更新します。SMA200等の計算用には最大240本の確定barを保持しますが、Jevへ生のOHLCとして渡す本数は1分60本、5分48本、15分32本、1時間24本です。

未確定の将来bar、判断時点より後でしか知り得ない値、API keyなどのcredentialは渡しません。テクニカル指標や過去損益は**観測情報**であり、「MAが上ならLONG」「連敗したら反転」のような固定ルールはコード側から課しません。

### スピリチュアル方向源

スピリチュアルモードは、Fifty+のentry / exit timingを新しく発明せず、**方向だけを別のルールへ差し替える比較実験**です。

- **月相**: 朔望月の前半をUP、後半をDOWNとする単純な二択
- **太陽星座の極性**: 固定カレンダーの12星座を陽/陰へ分け、UP / DOWNへ割り当てる二択
- **タロット1枚引き**: 各ラウンドで大アルカナをランダムに1枚引き、正位置をUP、逆位置をDOWNへ割り当てる
- **コイントス**: 各ラウンドで完全ランダムに表/裏を引き、表をUP、裏をDOWNへ割り当てるrandom control

これは占術の予測力や収益性を前提にした実装ではありません。月相・星座は決定論的で、タロットとコイントスは意図的に毎回ランダムです。コイントスはJevや他の方向源が単純な50:50方向選択より情報を持つかを見るための対照群として使います。

## 勝負幅

### FX

FXでは、Fifty+の勝負幅をpipsで指定します。

例:

```text
勝負幅: 5 pips
LONG:
  net +5 pips → WIN
  net -5 pips → LOSS
```

### BTC/JPY

BTC/JPYでは、勝負幅を円のネット損益で指定します。

例:

```text
勝負額: 500円
LONG / SHORT:
  net +500円 → WIN
  net -500円 → LOSS
```

JevPipのpaper brokerでは、spread、設定slippage、銘柄ごとのreference feeを反映した**ネット損益**でFifty+のTP/SLを判定します。

そのため、Fifty+でいう「1:1」は単なるチャート上の値幅ではなく、paper model上のコストを含めた対称な損益境界を指します。

実市場では、tick間の価格飛び、板の厚み、部分約定、実slippage、注文遅延などにより、実現損益が厳密な1:1にならない可能性があります。

## spread・勝負幅・放置実験の運用メモ

Fifty+はネット損益の ±X で決済するため、勝負幅を小さくするほどspread・手数料・slippageの比率が大きくなります。

新規建玉直後のネット損益は、すでに往復コスト分だけマイナス側から始まります。たとえばFXで勝負幅が5 pips、推定往復コストが3 pipsなら、価格変化だけで見るとWIN側まで進む距離はLOSS側よりかなり長くなります。

このため、JevPipでは次をコード側の安全条件として扱います。

- 設定した最大spreadを超えている間は新規取引しない
- 推定往復コストが勝負幅以上なら、建てた瞬間に損切り境界へ入るため新規ラウンドを開始しない
- 上記の待機中は新規方向判断を行わない。Jev版ではJev APIも呼ばない
- 条件が改善すれば自動的に再開する

### 放置して観測する場合

短い勝負幅はラウンド数を増やせる一方、コストの影響を強く受けます。

数時間そのまま動かして観測する用途では、5 pipsだけに固定せず、**10 pips / 15 pipsなど大きめの勝負幅も比較対象にする**のがよい研究条件です。これは利益を保証する推奨値ではなく、コスト比率とラウンド所要時間の違いを見るための実験設定です。

比較時には少なくとも次を同時に記録します。

- 勝負幅
- 実spread
- 推定往復コスト
- WIN / LOSS
- 純損益
- 1ラウンドの時間
- 方向源ごとの方向別勝率
- Jev / 月相 / 星座 / タロット / コイントスrandom controlとの差

特に、コストがある状態ではランダム方向の実現WIN率が必ずしも50%近辺になるとは限りません。Fifty+の評価では、単なる「50%超え」だけでなく、**同じコスト条件のrandom controlとの差**を見ることが重要です。

### 2026-09-21のUI確認で得た例

JevPipの実画面確認中に、以下を観測しました。

- USD/JPYでspread約9.9 pips、勝負幅10 pips
  - spreadとreference feeだけで新規直後のネット損益が損切り境界を超え、即決済と再エントリーを繰り返した
  - この観察を受け、往復コストが勝負幅以上なら新規ラウンドを開始しない安全弁を追加した
- EUR/JPYでspread約2.7 pips、勝負幅5 pips
  - 取引自体は成立するが、勝負幅に対するコスト比率が大きく、短時間に複数回の損切りが発生した
  - 挙動自体はFifty+のルールどおりであり、「小さい勝負幅ほどコストの影響が強い」ことを目視確認できた

この日は日本の祝日（敬老の日）で、確認時刻も日本時間の早朝でした。GMOクリック証券は、休日・祝日や早朝など市場流動性が低い状況ではspreadが拡大する場合があると案内しています。

ただし、この日のspread拡大を祝日だけに帰属させることはできません。時間帯、市場参加者、ニュース、通貨ペア固有の流動性など複数要因があり得るため、研究ログでは「祝日 / 時間帯 / 実spread」を別々に記録します。

## 方向を決めるタイミング

Fifty+では、方向判断をポジション保有中に繰り返しません。

```text
FLAT
  ↓
方向源: UP / DOWN
  ↓
1ポジション
  ↓
TP または SL
  ↓
FLAT（標準60秒待機）
  ↓
次の方向判断
```

Jev版ではポジション保有中と決済後待機中にJev APIを呼びません。スピリチュアル版でも同じタイミングを使い、待機終了後のfresh tickで月相・星座・タロット・コイントスの各方向源から次の二択を得ます。

JevPipでは決済後の再判断待機を標準60秒にしています。短く設定することもできますが、急変時に「決済 → 即再判断 → 反対方向へ再entry」が連続しやすくなり、いわゆる往復ビンタの形になりやすいため注意します。

Jev版では、この設計によりAPI token消費も「経過時間」ではなく**ラウンド数**に近づきます。


## この実験で見たいもの

Fifty+で特に見たいのは次です。

- JevのUP / DOWN勝率は長期的に50%を超えるか
- 勝率の優位性は特定の銘柄・時間帯・相場状態だけに偏っていないか
- 勝負幅を変えると勝率や1ラウンドの所要時間がどう変わるか
- FXとBTCで同じ傾向が出るか
- APIコストを含めても研究として継続可能なtoken効率になるか
- 単純なランダム方向選択と比べてJevに再現性のある差があるか

損益だけでなく、**方向判定そのものの統計**を見ることが重要です。

## Fifty+ と情報量

Fifty+の核は引き続き「JevがUP / DOWNだけを選び、executionはコード側が固定する」ことです。

初期実装では方向判定を純化するためJevへ渡す市場情報も強く絞っていました。しかし、1分足数本だけでは通常のトレーダーが得る相場の文脈より狭すぎるため、現在はmulti-timeframe・基本テクニカル・口座実績まで含む `trader_context_v1` を標準とします。

ここで増やしたのは**情報**であって**売買ルール**ではありません。将来ablationを行う場合は、情報の一部を外した条件と比較し、どのcontextが方向判定へ寄与したかを検証します。

## 注意

Fifty+は**収益を保証する手法ではなく、仮説検証のための実験ストラテジー**です。

50%を超える勝率が一時的に観測されても、それだけで将来の優位性や実売買での利益を意味しません。JevPip自体も現在はpaper tradingを前提としており、実注文は行いません。
