# JevPip 類似実装・競合調査メモ

調査日: 2026-09-19

この文書はJevPip実装開始前に確認した公開リポジトリと、採用した設計上の学びを記録する。

## 参考にしたリポジトリ

### rthomas24/jev-realtime-trading

- Jevに一つの巨大な「売買するか」判断をさせず、direction / reversal / setup / regime等をatomic questionとして分離している。
- Jev SDKをDeciderインターフェースの背後へ隔離している。
- model answerと、stop / target / position sizing / entry window等のコード側ルールを分離している。
- model callのlatency、tokens、実際に応答したmodel idを記録する。

JevPipではこの「Jev = 曖昧判断、code = hard rule」という分離を採用する。ただし固定thresholdを正解とはみなさず、設定・比較対象とする。

Repository:
https://github.com/rthomas24/jev-realtime-trading

### tyleree/jevbot

- Jev確率のcalibrationを主要な評価対象として扱う。
- Brier skill、baseline、record/replay、model versionの扱いなど、研究実験としての再現性を強く意識している。
- live-money code pathを持たず、paper-onlyを構造的に強制する。
- TypeSafe契約上、benchmark/performance resultsを公開しない方針を明示している。

JevPipでは巨大な構造をそのまま模倣せず、評価・再現性・公開範囲の考え方を参考にする。

Repository:
https://github.com/tyleree/jevbot

### zadescoxp/Jev-Trades

- 多数のテクニカル指標をstateへ投入し、buy/hold/sell、position size、stop loss、take profitまでJevへ判断させる。
- request/responseとpaper portfolioをJSONLへ記録する。

JevPipではログ構造は参考にする一方、position sizeやrisk limitをJevへ委ねる方式は採用しない。また、最初から大量指標を投入すると寄与が分からなくなるため、feature setはユーザーが選択できる構造にする。

Repository:
https://github.com/zadescoxp/Jev-Trades

### ajim3796/gmo_coin_fx_api

- GMO外国為替FX Public/Private/WebSocketのPython client。
- Public WebSocketのsubscription保持、再接続、pingを踏まえたtimeout設計が参考になる。

JevPip初期版ではPublic WebSocketだけに範囲を絞り、Private API credential自体を要求しない。

Repository:
https://github.com/ajim3796/gmo_coin_fx_api

### RikitoNoto/gmo-fx-py

- GMO外国為替FX APIのPython SDK。
- KLine等の型付きアクセスの参考になる。

Repository:
https://github.com/RikitoNoto/gmo-fx-py

## 採用した設計

1. Feature setを固定しない。
2. FeatureとJev questionを分離する。
3. Jev answerとresearch signal ruleを分離する。
4. spread / market status / safety / riskはcode-owned ruleにする。
5. raw tickはfeatureより先に保存する。
6. historical 1-minute KLine replayと、将来のtick replayを分ける。
7. random controlのような無意味なfeatureも対照実験として許容する。
8. 月相など非典型featureも同じFeature Registryへ載せる。
9. UIは初期段階では日本語を基本とし、code identifierは英語を維持する。

## TypeSafe結果の公開制約

2026-09-19時点のTypeSafe Master Customer Agreement 2.3(f) は、Servicesについてbenchmarkまたはperformance informationをpublishすることを禁止している。

したがってJevPipでは、

- 評価コード・評価方法・空のreport schemaは公開可能
- 実際のJev性能値、勝率、Brier score、PnL等は公開リポジトリへcommitしない
- 実測結果はgit-ignoredなローカルdataとして扱う

を初期方針とする。

Source:
https://typesafe.ai/legal/mca
